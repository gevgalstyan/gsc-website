Подготовить отдельный запрос на privacy-requests; отправить оператору по подтверждённому частному каналу. Указать только сведения, достаточные для нахождения аккаунта и цель/согласие, если известны. Оператор проверяет личность безопасно, регистрирует дату/объём, прекращает соответствующую обработку либо обосновывает иное законное основание, отвечает в применимые сроки и информирует задействованных обработчиков. Маркетинговый отказ не удаляет нужные для услуги записи.

## 5. Запрос удаления / деактивация — порядок

Запрос не равен автоматическому удалению. Оператор различает: временную деактивацию доступа; отзыв согласия; удаление данных без основания; сохранение обязательных учётных документов с ограничением целей/доступа. После верификации составить карту Auth→profiles→bookings→attendance→rewards→Storage→notifications→practice→audit→backups, решить удержания/обезличивание, сообщить основания сохранения и результат. Любой destructive action отдельно согласуется и проводится транзакционно с проверкой связей. Полный Auth delete сейчас может каскадно стереть историю; кнопка в браузере такого действия не выполняет.

## 6. Cookies и локальное хранение — проект уведомления

Сайт использует локальное хранилище для темы/языка, практики и сессии аккаунта; при входе Auth/защитные сервисы могут использовать дополнительные идентификаторы и cookies. При privacy-паузе практика сохраняется на этом устройстве, облачная история не удаляется. Выход и очистка site data могут удалить локальные настройки/прогресс и потребовать нового входа. Не найдено analytics/рекламных trackers в исходном приложении; фактические заголовки хостинга и сторонние сервисы нужно проверить. Для добавленных необязательных trackers сначала определить правовое основание и механизм выбора, не показывать фиктивную «принять всё» галочку ради вида.
