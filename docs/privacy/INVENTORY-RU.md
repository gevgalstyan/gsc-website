## Resend: проверенный код против неизвестной конфигурации

Канонический источник `supabase/auth-email-config.mjs`, подготовка `scripts/update-supabase-auth-email-config.mjs` (не live update). Семь шаблонов: confirmation, recovery, email_change, magic_link, invite, reauthentication, password_changed. Код не содержит собственного Resend API send/marketing flow. SMTP фактически настроен по сообщению владельца; аккаунтные настройки Resend/логи писем не читались. Отдельных custom login notifications не найдено; magic link/invite — возможности Auth, а не доказательство их использования. В шаблоне подтверждения есть информационные блоки о клубе: до открытия согласовать, что security mail не превращается в рекламу.

По [Resend GDPR](https://resend.com/security/gdpr): содержимое сообщений, delivery logs, webhook/account data хранятся в США; sending region меняет отправку, не место хранения. Free/Pro/Scale — 30 дней email/logs, Enterprise настраиваемый; backups 7 дней; при прекращении использования остатки удаляются в пределах 90 дней. Тариф/договор этого аккаунта неизвестны. SCC/DPF не заменяют российскую оценку.

Запросить у Resend: юрлицо/адрес/контакты, DPA, subprocessors/countries, реальные retention/deletion и доступ support, сведения для оценки по ст.12, обработку bearer-like token links и security controls. Решение о сохранении Resend принимать отдельно от локализации первичной базы; иностранный сервис не объявлен автоматически запрещённым. [Яндекс 360](https://www.yandex.ru/support/yandex-360/business/admin/ru/security/personal-data) заявляет хранение в РФ: кандидат SMTP, но нужно подтвердить транзакционные лимиты, договор для НПД, SMTP-подключение Supabase, bounce/delivery, DKIM/SPF/DMARC, retention и отправку на зарубежные почтовые ящики. Замена не выполнялась.
